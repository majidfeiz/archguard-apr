# Benchmark architecture-profile policy

Authors may classify documented package layers, dependency direction, tests versus production code,
public/internal API boundaries and documented plugin/adapter boundaries. Layout alone is evidence of
structure, not architectural intent. Each rule needs rationale, author, review state, exceptions,
coverage and unassigned-module counts. Profiles progress `DRAFT` → `REVIEWED` → `FROZEN`; excluded
profiles remain recorded. Construction and review happen before repair outcomes. Candidate results
cannot change a rule; any later amendment creates a new version. Only frozen profiles enter final plans.
