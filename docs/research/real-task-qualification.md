# Real-task qualification

Qualification order is metadata → acquisition → license audit → reproduction → analysis → profile
draft → human review → infrastructure pilot → protocol freeze. Candidate selection is seeded before
repair and may use supported Python/platform, source/license availability, declared tests, private
dependency/service absence, resources and project/failure diversity. It cannot use ArchGuard/model
success, gold similarity, desired outcomes or reference-patch ease.

No task reached selection in this phase because benchmark/dataset and per-project license review is
incomplete and this ARM host cannot establish Linux/x86 evaluator readiness. Therefore acquired real
tasks, reproduced baselines, stability classifications, evaluator qualifications and architecture
analyses are all zero observed. Failed or blocked candidates were not silently replaced.
